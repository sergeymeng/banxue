### 插话与取消测试细节

- 输入 32ms 的 Silero 概率帧；连续 96ms 高概率才本地静音；单个概率峰值不触发，640ms 停顿不结束发言，预留音频不超过 480ms。这里的门控单测不声称模型能可靠识别所有咳嗽和噪声。
- 浏览器使用真实 Silero v5 和 AudioContext。将合成中文“等一下，为什么要乘以内层函数的导数？我还没有听懂。”注入 MediaStream，在 mock 云端没有给出任何转写前，确认老师播放上下文已经 suspended、采集仍 running。
- 暂停保留队列，白名单短应答和空转写恢复，不创建新 LLM 付费请求；连续新问题则取消前轮，新轮开始后无旧 ID 的文本/音频输出。
- 播放开始/排队时没有 completed 回执；音频结束且句段收齐后才记录完成；局部打断只记近似毫秒位置。
- ASR、TTS、截断 LLM 流在取消/异常后保留正数不确定预留；预算不足时在建立供应商连接前拒绝。
- Key 不出现在公开配置或 usage，假 Key 在桌面设置文件中是密文；WS 对无票据、错误 Origin、错课堂票据、票据重用均拒绝。

## 已有的时延实测与不能推出的结论

浏览器合成输入的最近一次结果保存在 [browser-synthetic.json](voice-evaluation/browser-synthetic.json)。开发回归观察到（非受控统计基准）：

- 注入测试音频至测试端观察到 `begin` 事件：151ms、141ms；最终前端回归为 205ms。
- VAD 确认回调内，调用本地 gain 静音与 suspend：0.3～0.4ms，最终回归为 0.3ms。
- 真人开口 → 扬声器实际停止出声：**未测**。

这些是合成输入与软件事件时间。注入时间包含夹具解码/调度，起点不是人工标注的首个发音；回调耗时不包含设备、模型帧处理及扬声器缓冲。因此不能将 141ms 或 0.4ms 写成达到了 300ms 真人指标，也不能用它推断扬声器回声误触发率。

目标的测量方法：真人在老师播放中开口，使用同一时间基准的双通道外部录音/采集，分别记录学生语音与老师扬声器输出；人工或波形标注学生首个有效语音起始与老师最后可闻输出之差。至少记录耳机和扬声器条件下各 10 次的单次延迟、P50、最大值；保留误触发/漏触发次数。应用内“插话测量”只提供诊断辅助，不能替代声学测量。

## 真人最短复测清单

1. 在应用内选择地域、应用预设、填 Key 并保存。开启语音，核对系统麦克风权限；从简单一句话确认转写 → 真实文本回复 → 声音。Key 不发到聊天。
2. 戴耳机说“这题为什么用 chain rule”；老师讲解时依次插入“等一下”“为什么”“我没懂”，每次确认旧声音停止、新回答结合原题，连续三次没有两轮重叠。
3. 说“嗯、对”检查恢复；说一句话中间停 0.5～1 秒，确认没有被急促抢话；读“负 x 的二次方”“分母”“倒数”，检查确认/修改入口和原始转写。
4. 改用扬声器，以常用音量重复；只让老师说话时不应频繁自打断，再加入键盘声、咳嗽和环境噪声，记录误触发及漏触发。若有问题，先用耳机并按记录校准，不宣称 AEC 参数已通过测试。
5. 静音、立即停止、结束语音、切换页面、拔掉设备/断网各一次；确认声音停止、麦克风系统指示灯消失、打字可用，用量中取消请求保留预留。

接口冒烟与主观体验可以几分钟完成；300ms 声学目标需另按上述双通道测量完成。当前没有自动教师板书动作同步、完整手写评分或真实学生学习效果验证。
