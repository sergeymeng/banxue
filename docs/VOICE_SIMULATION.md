# 语音课堂仿真

可以先在无 Key、无付费请求的情况下开发和调试完整链路，再做真实接口和真人设备联调。仿真发现的代码问题当场修复，不需要积累到最后。

## 运行

```bash
cd frontend
npm run test:voice-sim
# 查看浏览器中的执行过程
npm run test:voice-sim -- --headed
# 单步调试连续三次插话
npm run test:voice-sim -- --debug -g 'three natural interruptions'
```

使用已安装的 Python、Node 和 Playwright Chromium；首次安装环境按 README 执行依赖安装，缺浏览器时在 frontend 运行 `npx playwright install chromium`。测试占用 3100/8100，不能与普通 `test:e2e` 同时运行；端口占用会报错，不会接管其他服务。

一条命令启动专用后端和现有前端，建立真实本地 WebSocket，驱动课堂，然后退出进程。界面下方明确标记“语音仿真 · 本地模拟供应商 · 不调用云端”。`backend/tests/voice_sim_server.py` 只供测试进程使用，正式应用没有仿真开关或调试路由。测试清除配置环境变量并关闭 .env 加载，数据只写入 `backend/data/e2e/voice-sim`；不要把此测试服务器暴露到局域网或公网。

## 哪些是真的，哪些是模拟的

| 层次 | 仿真方式 |
|---|---|
| 页面、语音客户端、音频队列、轮次过滤、课堂状态、教学策略、费用账本 | 使用产品代码 |
| 麦克风输入 | 假设备授权后，将已有的合成中文 WAV 注入 MediaStream；不是用户录音 |
| VAD、预留缓冲、停顿判断 | 运行实际 Silero v5、ONNX Runtime、AudioWorklet 和本地门控 |
| 本地网络 | 真实 HTTP 与 WebSocket；票据、来源、课堂绑定使用产品校验 |
| 千问 ASR/TTS 适配器 | 使用产品适配器，传输层替换为内存事件；检查音频格式和热词参数 |
| 千问 LLM 适配器 | 使用产品 SSE 解析与费用逻辑，httpx MockTransport 返回可控流 |
| ASR 文本 | 场景预设，不是对夹具的真实识别结果；不能用于准确率评估 |
| TTS 音频 | 低音量合成纯音，用来验证 PCM 调度、暂停与清理；不代表千问音色 |
| 费用、用量 | 仿真数值，仅在隔离测试账本中验证结算与不确定预留；没有真实账单 |

测试覆盖流式转写/回复/播放回执、连续三次自然插话、迟到文本和音频、短应答/空转写恢复、思考停顿、数学歧义确认、ASR/LLM/TTS 故障、LLM 超时、断线、设备断开和离开课堂。失败请求必须只有一次上游尝试，显式再次提问可以恢复。每个场景结束后断言媒体轨道与 AudioContext 关闭、服务端任务归零；播放调度区间不得重叠。

按键声和微弱语音残留是合成输入，只观察 VAD 暂停与空转写恢复。模拟是在浏览器采集后注入，未模拟真实房间声场，也没有测试浏览器的声学回声消除。不能据此声称咳嗽、键盘声或扬声器回声不会误触发。

每次运行自动写出：

- [结构化结果](voice-evaluation/simulation-summary.json)

- 详细事件、费用流水、失败截图和浏览器 trace：`frontend/test-results/voice-sim`，由 Git 忽略。

插话指标采用同一浏览器 `performance.now()`：从合成音频调用 `source.start()` 前的调度标记，到老师 AudioContext 的 `suspend()` 调用。它包含合成输入调度和 VAD 处理，不等于真人语音起点，也不包含扬声器输出缓冲。报告列出每次样本，不把它当作 300 ms 真人停声目标已经达成。

2026-10-31 本轮检查修复：重连时将“被打断”回执与“已播放完成”回执分开恢复；关闭转写保存时，空文本也能安全构造上下文。新增保留/不保留转写两种回归测试，避免将只听到开头的句段当成已经教过。

## 最后的真实联调

1. 在桌面设置中应用千问推荐预设，填写自己的 Key 并保存；不要把 Key 发到聊天。先戴耳机完成一次真实转写 → 回复 → 播放，核对真实 usage、地域和权限。
2. 播放中连续说“等一下”“为什么”“我没懂”，再试“嗯”、一句话中间停顿、修改转写。确认结合原题继续、没有旧声音重现。
3. 改用扬声器，以常用音量测试老师独说、键盘声、咳嗽和学生插话；按 [语音验证报告](VOICE_TEST_REPORT.md) 的双通道声学测量方法记录真实停声延迟与误触发率。

本轮没有新增第三方依赖。已有音频组件及 tldraw 的许可边界仍见 [依赖说明](DEPENDENCIES.md)。
